# 网络消息处理

套接字Socket是点对点（应用对应用）连接不同主机的API，工作在TCP/IP协议（应用层、传输层、网络层、链路层）之上。使用Scoket连接时需要指定IP地址（主机）和端口号（应用）。

## Client请求

Client连接Server，Server监听对应端口；Client创建请求消息并发送至Server；Server接受并响应请求。

Client通过绑定在GameObject上的单例NetWork.NetClient，使用Init(string serverIP, int port)初始化连接的IP地址和端口号，Connect()判断网络连接状态并处理异常（socket没有及时关闭，连接地址为空等），DoConnect()创建Socket实例，并进行连接。通过SendMessage(NetMessage msg)将消息加入到消息队列，Update()中判断是否保持连接，判断有无接收信息，判断消息队列是否有信息需要发送。

## Server监听

 Server通过单例NetWork.NetServer类监听Client消息。TcpSocketListener的静态实例ServerListener的Init()对ServerListener进行初始化，创建Socket，监听对应端口，并且订阅SocketConnected事件；NetService.OnSocketConnected(object sender, Socket e)创建一个NetConnection<NetSession> connection用于保存连接客户端的信息和socket。SocketConnected事件的处理器为NetService.OnSocketConnected(object sender, Socket e)，当有新的Client进行连接，Server使用Acept创建对应的socket后触发。

请求消息通过使用Socket接收之后，进行解析，通过判断解析过后的msg在MessageDispatch中回调对应的消息处理器。

MessageDistributer泛型单例类封装了事件的订阅和事件的激活。

MessageDispatch泛型单例类判断msg类型，通过使用MessageDistributer中的RaiseEvent进行msg信息到达的事件回调。

订阅msg信息到达事件的Service单例类中每一种msg都有对应的Service类与之对应，MessageDistributer中的订阅方法，进行事件的订阅并且有与之匹配的处理方法，

消息的订阅类——msg对应的Service，在Init中订阅，可以通过智能提示，直接生成相关的处理器方法。

# 基础场景与UI

Canvas是所有UI控件的父节点。Render Mode中Overlay模式Canvas及其子节点永远在屏幕前，常用于制作UI界面，Camera模式基于摄像机，与摄像机之间有一定距离，可在之间添加一些3D粒子效果；WordSpace下UI处于3D空间，可用于制作血条，名字等。

UI控件有轴点Pivot（物体的位置变化或者旋转情况的依照点，物体的PosX PosY是根据轴点到达锚点的距离距离计算）和锚点（用于确定物体的位置和拉伸情况）。

# 注册与登录

1. 获取用户输入，Client的UIScript做初步判断。
2. 将正确的输入传给UserService，UserService做打包处理并且发送给服务器。
3. Server订阅相关消息，并做处理=>根据与数据库的交互结果填充响应信息。
4. Server往Client发回响应信息。
5. Client的UserService订阅Reponse消息，并做处理=>利用UnityAction<>调用控制相关UI的方法。

- 直接进行逻辑处理的类。
- 含有一个NEntity方便用于客户端与服务器的交互。

- 用于客户端与服务器的交互的协议类。

- 字段与数据库的列名对应的类，用于存储从数据库获取的数据。

# Manager

Manager用于管理一组类实例，含有一个数据结构用于存储要管理类的实例以及Init、Dispose、Add、Remove、Clear等常用方法。

- Init用于自动生成要管理的实例，如从配置表读取数据进行实例的创建。
- Dispose用于销毁Manager类。
- Add用于从外部添加实例。
- Remove移除数据结构中的实例。
- Clear清空数据结构。

地图上图标的制作：UIImage的source image为制作的mask，并添加Mask组件，作为要展示图片的父节点。

# 移动同步

为Server和Client创建EntityManager。CharacterEnter之后产生EntityId，即修改Server（CharacterManager，Map）和Client（CharacterManager，GameObjectManager）端存储Character相关的数据结构的key值。进入时在哪里添加、创建，退出时就在哪里删除、销毁：

- Server端的Map中移除->给Client发送移除角色的信息->Server的CharacterManager移除->Server的EntityManager移除。
- Client端的MapService订阅Leave信息，处理：CharacterManager的Remove->回调OnDestroyCharacter为GameObject中的销毁GameObject的方法->EntityManager移除对应的Entity调用EntityRemoveNotifies对应的方法销毁其他创建CharacterGameObject产生的东西如血条...->CharacterManager移除掉对应的Character。

MainPlayerCamera设置为单例类，CurrentMapId在GameLeave时候重置为0，PlayerInputController调用MapService进行信息的发送，服务器创建MapService进行同步请求的订阅和处理，服务器处理中调用Map进行Entity的更新和发送给其他的角色，客户端的MapService进行订阅处理，调用EntityManager进行对应EntityData的更新，并且回调EntityController进行OtherGameObject的控制。
