## Lua底层

由于lua是一个跨平台的脚本语言，会根据平台位数(16bitbit)、平台类型(linuxwindows)、语言标准(C89C99)、以及编译参数等开启预编译选项，导致基本数据结构的字长和类型会动态变化。

Lua的基本数据表示方式是type + union的方式，根据不同类型映射到union的不同结构上面, 统一的表示结构lua_TValue。

```lua
typedef union Value {
  GCObject *gc;    /* collectable objects */
  void *p;         /* light userdata */
  int b;           /* booleans */
  lua_CFunction f; /* light C functions */
  lua_Integer i;   /* integer numbers */
  lua_Number n;    /* float numbers */
} Value;

struct lua_TValue {
  Value value_; 
  int tt_;
} TValue;
```

lua简单数据类型bool、整型、浮点型都是统一用lua_TValue来表示，消耗内存为sizeof(lua_TValue) = 16字节。因此相对C\C++表示整型的char\short\int\int64_t来说，这种数据结构的表示法虽然比较统一，但比较消耗内存。还有一些复杂的数据结构，统一封装在GCObject中。

```lua
union GCObject {
  GCheader gch;
  union TString ts;
  union Udata u;
  union Closure cl;
  struct Table h;
  struct Proto p;
  struct UpVal uv;
  struct lua_State th;  /* thread */
};
```



## 1、Table的底层

``` Lua
typedef struct Table {
  CommonHeader;
  lu_byte flags;  /* 1<<p means tagmethod(p) is not present */ 
  lu_byte lsizenode;  /* 以2的lsizenode次方作为哈希表长度 */
  struct Table *metatable /* 元表 */;
  TValue *array;  /* 数组 */
  Node *node; /* 哈希表 */
  Node *lastfree;  /* 指向最后一个为闲置的链表空间 */
  GCObject *gclist;
  int sizearray;  /* 数组的大小 */
} Table;
```

Lua中对于表的设计，是基于数组和散列表，和其他语言不同，对于数组的下标是从1开始的（可自定义索引），对于散列表而言，只要其键值不为nil，都可以存储在其中。Table将整数存储在以sizearray为长度的数组array中，将其他数据类型存储在以lsizenode长度的哈希表中。不论array还是hashtable都是连续的内存分布。

插入键时会动态调整：

- 当插入整数类型时，会判断当前区间里，array中存储的数量是否大于其长度的一般，否则该数据会被存储在node中。这样设计，可以减少空间上的浪费，并可以进行空间的动态扩展。
- 非整数类型的键会被全部分配到node里。Hash冲突时会将该数据存放在lastfree中，并将当前node链接到表中（空闲链表来维护冲突节点）。

无论是array还是node表，都是以2的倍数进行扩展的。比较有区别的是，array数组sizearray记录的是真实大小，而node表的lsizenode记录的是2的倍数。当node表空间满的时候，才会重新分配array和node表。

## 2、Sting的底层

Lua中字符串是被内化的，每个存储字符串的变量存放的是字符串的引用，因此字符串在Lua中是不可变的。每次创建字符串时，先查找该字符串是否存在，否则才创建新字符串。内化字符串可以提高查找的效率（只比较散列值而不需要逐数据比较）和节省内存。Lua虚拟机中使用散列通存放所有字符串。

String又细分为短字符串LUA_TSHRSTR和长字符串LUA_TLNGSTR两种，默认长度小于40的为LUA_TSHRSTR，使用全局stringtable进行管理。即所有短字符串都在stringtable中存放，相同字符串只会有一份实际数据拷贝，每份相同的TString对象只是存放一个hash值，用来索引stringtable（链表节点动态分配）。而长字符串则跟普通的GCObject没有差别，相同字符串在内存都是单独一份数据拷贝。在开发中可以适当避免`..`拼接运算产生大量字符串的产生。可以考虑使用string.format来格式化字符串

当创建字符串时，先计算其散列值即索引，然后在该位置存放此字符串。冲突使用拉链法解决。为了防止桶的数据过度导致在链表上查找很慢，会重新分配桶数量。对桶的缩小和扩容都是翻倍的。

在Lua5.1中，没有区分长短字符串，所有的字符串统一在stringtable中存在唯一拷贝。猜想这种改变一是因为长字符串出现相同的情况比较少，二是lua5.1的方式长字符串TString计算Hash是抽取部分字符进行运算，这样的计算方式可能被伪造导致不同字符串的hash值一样，但要是所有字符全用来计算hash又比较耗时。

## 3、Lua与C#交互过程及原理

C# Call Lua：由C#文件先调用Lua解析器底层dll库（由C语言编写），再由dll文件执行相应的Lua文件。C#与Lua进行交互主要通过虚拟栈实现，栈的索引分为正数与负数。如果索引为正数，则1表示栈底，若果索引为负数，则-1表示栈顶。由C#先将数据放入栈中，由lua去栈中获取数据，然后返回数据对应的值到栈顶，再由栈顶返回至C#。

Lua Call C#：

- Wrap方式：首先生成C#源文件所对应的Wrap文件或者编写C#源文件所对应的C模块，然后将源文件内容通过Wrap文件或者C模块注册到Lua解释器（Lua虚拟机）中，然后由Lua去调用这个模块的函数。。
- 反射方式：当索引系统API、dll库或者第三方库时，如果无法将代码的具体实现进行代码生成，可采用此方式实现交互，但执行效率低。

## 4、GC底层原理

Lua采用标记清除算法。

Lua 5.0使用双色标记清除算法（白色待访问，黑色为被引用），这要求GC过程中标记和回收要连续进行，意味着GC过程中程序要停下来，代价较大。

从5.1开始，Lua采用三色增量标记清除算法（新增灰色表示该对象已扫描但该对象引用的其他对象未被访问），不必再要求GC一次性扫描完所有对象，而是可以中断再恢复继续执行的。然而，当一个对象在标记过程结束后被创建，则其标记为白色，意味着该对象会被认为是未引用对象而被回收。因此Lua引入**双白色**概念，即当前白色和非当前白色。二者轮流成为GC过程中需要被清楚的标记。

在保存全局状态的global_State结构体中，有存放当前GC白色、GC状态（暂停阶段，传播阶段即检查引用阶段，字符串回收阶段，回收阶段，终止阶段）、存放GC对象的链表、当前回收位置、下一个待回收对象等。

每个新创建的对象都是白色的，并存储在扫描的链表上。初始阶段遍历root链表上所有节点，将其颜色改为灰色，加入到gray链表；对于字符串对象省略灰色直接进行回收。进一步遍历gray链表中对象，将其与引用对象标记为黑色。最后对可回收对象进行回收，并将GC切换为暂停状态。
