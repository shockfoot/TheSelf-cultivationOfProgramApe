## 1、值类型和引用类型的区别

- 在局部变量中，值类型变量存储在栈中，直接存储值。引用类型变量也存储在栈中，但存储所指对象的引用，而该对象则存储在堆中。
- 在赋值时，值类型传递值，引用类型传递引用，而不复制其指向的对象。
- 值类型继承自`System.ValueType`且不能被继承，引用类型继承自`System.Object`，只要不是密封的就可以被继承。
- 值类型不能为`null`。可空类型只是一种语法形式，CLR在底层进行了处理。
- 值类型的默认值为0，引用类型的默认值为`null`。

## 2、结构体和类的区别

- 结构体是值类型，存在栈中；类是引用类型，存在堆中。
- 结构体可以不使用`new`，类需要使用`new`实例化对象。
- 结构体成员变量（除静态成员变量外）在声明时不能赋初值。
- 结构体不能声明无参构造函数。
- 结构体声明有参构造函数后，必须在构造函数内初始化所有成员变量，且无参构造函数不会被顶掉。
- 结构体不能声明析构函数。
- 结构体不能被继承，所以成员不能使用`protected`访问修饰符。
- 结构体不能使用`static`修饰符，即不存在静态结构体。
- 结构不支持抽象，类可以使用`abstract`。

结构体多用来存储数据的集合如位置、向量等。当需要用到继承和多态时，使用类。只需要传输值时使用结构体。

## 3、栈和堆的区别

- 值类型大多分配在栈上，引用类型都分配在堆上。
- 栈基于线程，初始大小为1M，由操作系统管理，其上变量在作用域完成后就被释放，效率高；堆基于进程，大小根据运行情况而定。

## 4、结构类型对象可能分配在堆上吗？

两种情况会将结构类型对象分配在堆上：

1. 结构类型是类的一个字段或属性，会随类一起分配在堆上。
2. 对结构进行装箱后会在堆中存储。要避免对值类型装箱，性能消耗大。

## 5、按值传递和按引用传递

按值传递是是在参数传递过程中传递变量的值，如果是值类型则传递值，如果是引用类型，则传递引用。

按引用传递传递是在参数传递中使用`ref`或`out`关键字，传递该值的内存地址。

## 6、ref和out的区别和相同点

`ref`引用参数和`out`输出参数都指示编译器传递参数地址，在行为是相同的。二者都不可以重载，所以从编译角度看，二者的实质是相同的。

`ref`和`out`的使用机制不同，`ref`要求参数在使用之前必须显示初始化，`out`要求参数必须在方法内初始化。

## 7、C#支持哪几个预定义的值类型？C#支持哪些预定义的引用类型？

值类型：整数、浮点数、字符、布尔、Decimal。

引用类型：Object，String。

## 8、结构体中的引用类型在内存中如何存储？

结构体存储在栈上，引用类型字段也存储在栈上，直接存储其值即所指对象的引用，而该对象存储在堆中。

## 9、什么是装箱和拆箱？

装箱是将值类型转换为`Object`类型或此值类型实现的任何接口类型。拆箱指将`Object`类型转化为值类型或接口类型转化为实现该接口的值类型。

## 10、装的是什么？拆的是什么？什么是箱子？

装的是值类型，拆的是装箱后的引用类型对象。箱子就是存放了值类型字段的引用类型对象实例。

## 11、箱子放在哪里？

托管堆上。

## 12、装/拆箱有什么性能影响？

因为装/拆箱都涉及内存的分配和对象的创建，都有较大的性能开销。其中由于引用类型对象的创建更加复杂，所以装箱性能开销更大。此外，由于堆上的操作效率和GC的原因，过多的装/拆箱也会降低效率。

## 13、如何避免隐式装箱？

实在要装箱时使用显示装箱来减少装箱次数。在字符串拼接时提前转成`string`。使用泛型。

## 14、箱子的基本结构

两部分：存放值类型值的和引用类型的标准配置（TypeHandle和同步索引块）。

## 15、装箱的过程

1. 先在堆中申请内存，大小为值类型所占内存加上准配置（TypeHandle和同步索引块）的额外空间。
2. 将值类型的值拷贝到新分配的内存中。
3. 返回新对象的地址。

## 16、拆箱的过程

1. 检查实例对象的有效性：是否为`null`，装箱类型和拆箱类型是否一致等。
2. 指针返回，即获取装箱对象中值类型值的地址。
3. 将该值拷贝到栈上。

## 18、字符串是引用类型还是值类型？

引用类型。

## 19、字符串连加处理时，最好采用什么方式，理由是什么？

## 23、实现字符串反转算法。

方法一：StringBuilder

``` C#
public string Reverse(string str)
{
    if (string.IsNullOrEmpty(str))
        throw new ArgumentException("参数不合法");
    StringBuilder sb = new StringBuilder(str.Length);
    for (int i = str.Length - 1; i >= 0; --i)
    	sb.Append(str[i]);
    return sb.ToString();
}
```

方法二：双指针

``` C#
public string Reverse(string str)
{
    if (string.IsNullOrEmpty(str))
        throw new ArgumentException("参数不合法");
    char[] res = str.ToCharArray();
    int head = 0, end = res.Length - 1;
    while (head < end)
    {
        char tempChar = res[head];
        res[head++] = res[end];
        res[end--] = tempChar;
    }
    string strRes = new string(res);
    return strRes;
}
```

## 25、所有类型都继承自System.Object吗？

基本上是的，所有的值类型和引用类型都继承自`System.Object`。接口是一个特殊类型，不继承自`System.Object`。

## 26、解释virtual、sealed、override和abstract的区别。

- `virtual`修饰方法，表示该方法是虚方法，即可以被子类选择性重写。
- `sealed`修饰类，即密封类，表示该类不能被继承。修饰方法，与`override`，表示实现父类虚方法，但禁止子类重写该方法。
- `override`修饰方法，需要配合`virtual`使用，表示子类重写父类中的同名方法。
- `abstract`修饰类或方法，表示抽象类或抽象方法。抽象类不能被实例化，只能通过继承使用；抽象方法不能实现，只能通过子类实现。

## 27、接口和类的异同。

相同点：

- 接口和类都是引用类型的。
- 接口和类都可以包含属性、方法、索引器和事件。
- 接口、类和结构都可以实现多个接口。
- 接口类似与抽象类，实现接口的任何非抽象类都必须实现该接口的所有成员。
- 接口和类都可以分部。

不同点：

- 接口不能实例化；类（除了抽象类）可以实例化。
- 接口只能包含方法或属性，不能包含其实现，不能使用修饰符；类可以包含字段等成员，可以包含具体实现。
- 接口可以多实现；类只能单继承。
- 含义不同。接口是一组行为的规范，是“can do”的关系；类是概念的统一，即“is a”的关系。

## 28、抽象类和接口的区别

- 抽象类单继承；接口支持多实现。
- 抽象类是概念的统一，即“is a”的关系；接口是行为的规范，是“can do”的关系。
- 抽象类中可以包含普通方法（具体实现）和字段等；接口中不能包含具体实现和字段，接口中的方法不能使用修饰符。
- 子类可以不重写抽象类中的抽象方法，即延用抽象类的方法；实现接口的类必须重写接口中的方法，并给出具体实现。
- 在抽象类中新增方法，子类中可以不作处理；在接口中增加方法，实现类必须提供新定义的方法的实现。
- 抽象类只能作用于引用类型；接口可以作用于值类型（枚举可以实现接口）和引用类型。

## 29、重载和重写的区别

重载：当类包含两个名称相同但签名（参数列表）不同的方法时发生重载。重载提供在语义上完成相同而功能不同的方法。

重写指在继承时，子类可以重写父类中的虚方法。

区别：

- 重载是同一个类中多个方法之间的关系，是水平关系；重写是子类和父类之间一对方法的关系，是垂直关系。
- 重载要求参数列表不同；重写则参数列表相同。
- 调用重载的方法时，根据实参表和形参表来选择方法执行；调用重写时根据对象的类型来决定。

## 30、在继承中new和override相同点和区别？

`override`表示子类重写父类中同名的虚方法，要配合`virtual`使用。`new`表示子类不重写父类中的同名虚方法。

相同点：指向子类对象的子类引用都可以具有自己的行为。

不同点：指向子类对象的父类引用在调用这两个方法时具有不同的行为。

## 31、以下代码输出什么？为什么？

``` C#
public void DoTest()
{
    B1 b1 = new B1(); B2 b2 = new B2();
    b1.Print(); b2.Print();

    A ab1 = new B1(); A ab2 = new B2();
    ab1.Print(); ab2.Print();
}
public class A
{
    public virtual void Print() { Console.WriteLine("A"); }
}
public class B1 : A
{
    public override void Print() { Console.WriteLine("B1"); }
}
public class B2 : A
{
    public new void Print() { Console.WriteLine("B2"); }
}
```

`b1.Print(); b2.Print();`输出`B1 B2`。`ab1.Print(); ab2.Print();`输出`B1 A`。

因为`B2`没有重写父类的方法，而是隐藏，所以指向`B2`类型对象的父类引用`ab1`调用方法时执行父类的方法，而该方法未被重写。

## 33、类中定义的静态字段存储在内存的什么地方？为什么不会被GC回收？

类中的静态字段随类型对象存储在内存的加载堆（Load Heap）上，因为加载堆不受GC管理，其生命周期随AppDomain，不会被GC回收。

## 34、const和readonly的区别

`const`用来声明编译时常量，`readonly`用来声明运行时常量。都用来表示常量，区别有：

- 初始化位置不同。`const`必须在声明时初始化；`readonly`可以在声明和构造函数中初始化。
- 修饰对象不同。`const`可以修饰类的字段和局部变量；`readonly`只能修饰类的字段。
- `const`是编译时常量，在编译时确定其值，且值在编译时被内联到代码中；`readonly`是运行时常量，在运行时确定该值。
- `const`默认是静态的；`readonly`需要显示声明静态。
- `const`只能修饰基元类型或值为`null`的其他引用类型；`readonly`可以用于任何类型。

## 35、哪些类型可以定义为常量？使用常量有什么风险？

基元类型（基础数值类型）或值为`null`的其他引用类型。常量不支持跨程序集版本跟新。在常量改变后，需要编译所有使用该常量的代码。

## 36、字段和属性的异同

相同点：属性是字段的自然扩展，与字段同名（除了首字母大写），访问字段和属性的语法相同。

不同点：

- 属性是对字段的封装，用于灵活、安全的访问字段。
- 属性允许在访问器中编写代码。
- 属性允许控制访问器的可访问性，从而提供只读或可读写的功能；出于面对对象的封装性，字段一般不设计为`public`。
- 属性可以是虚的，支持重写。

## 37、静态成员和非静态成员的区别

- 静态成员使用`static`修饰，在加载类的时候被加载，随类型对象存放在Load Heap中，属于类，通过类进行访问；非静态变量在对象被实例化，随类放在托管堆中，属于对象，通过对象访问。
- 一个类的不同实例对象的同一静态变量是同一个值；一个类的不同实例对象的同一非静态变量可以是不同值。
- 静态函数中不能使用非静态成员。

## 38、自动属性的风险

自动属性中的私有字段由编译器自动命名，不受开发人员控制。后期不宜随意修改，会在序列化中导致字段值的丢失。

## 39、特性是什么？如何使用？

`Attribute`特性是关联了一个目标对象的一段配置信息，本质上是一个类，为目标元素提供关联附加信息，这段附加信息存储在dll内的元数据中，本身没有什么意义。运行时可通过反射的方式来获取配置的特性信息。

## 41、C#中的委托是什么？事件是不是一种委托？

委托类似于C/C++中的函数指针，是面向对象且安全的，允许将方法作为参数传递。

- C#中的委托都继承自`System.Object`。
- 委托类型的声明与方法签名类似，有返回值和参数。
- 委托是一种可以封装方法的引用类型，把方法当作指针传递，可以不必在编译时知道具体调用方法。
- 事件是一种特殊的委托，事件的内部是基于委托实现的。

## 42、委托和事件在使用上的区别

委托和事件都是对方法的封装。

- 事件是一种特殊的委托。使用时必须先声明该事件的委托类型，然后使用`event`关键字声明事件。事件被触发时会调用委托。
- 事件只能出现在结构体、类和接口中。
- 事件在外部使用时只能订阅`+=`、取消订阅`-=`，而不能直接使用`=`赋值。
- 事件不能在外部触发。
- 通常使用委托表达回调，使用事件表达外发的接口。

## 43、简述引用对象的生命周期

`new`创建对象并分配内存，对象初始化，使用和操作对象，（非托管）资源清理，GC。

## 45、什么是垃圾？

垃圾就是堆上没有被引用的对象。

## 46、GC是什么，简述GC的工作方式

GC是垃圾回收（Garbage Collect）的缩写，是.NET核心机制之一，用于垃圾回收。

基本工作原理是在分配新对象内存空间时，如果空间不够了，会触发GC。触发后会遍历堆上所有对象，将被使用的对象标记为可达对象，将不可达对象回收释放，将可达对象转移到一个另一块连续的内存（压缩）。

## 47、GC主要流程

1. 标记。先假设所有对象都是垃圾，从应用根Root遍历堆上所有对象，生成可达对象图。将还在使用的对象标记为可达对象（在同步索引块中设置标识位）。
2. 清除。对不可达对象进行回收，其中普通对象直接回收，实现了析构函数（终结器）的对象单独处理。
3. 压缩。清除后内存不连续。将剩下的对象转移到一个连续的内存，修改转移后的地址。

## 48、GC在什么情况下进行？

- 内存不足（Gen 0满）时。
- Window报告内存不足时，CLR会强制GC。
- CLR卸载AppDomain时，GC回收所有内存。
- 手动调用`GC.Collect`时。
- 其他情况，如主机拒绝分配内存，物理内存不足，超出短期存活代的存段门限。

## 49、using()语法如何确保对象资源被释放？如果内部出现异常依然会释放资源吗？

`using()`只是一种语法形式，其本质是`try...finally`结构，可以保证Dispose始终被执行。

## 50、C#的析构函数是什么？为什么有的不建议使用析构函数？

C#的析构函数实际上就是终结器Finalize。

不建议使用析构函数的原因在于：Finalize的性能不好，实现中终结器的对象需要维护终结队列和Freachable列表，并且需要GC两次才能被释放；Finalize的原理很多人不清楚，滥用会导致内存泄露。
