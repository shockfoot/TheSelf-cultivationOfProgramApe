## 51、Dispose和Finalize的区别

二者都是.NET提供的释放非托管资源的方式，主要区别在于执行者和执行时间的不同：

- Dispose由对象手动调用；Finalize由GC自动调用。
- Dispose调用后立即释放非托管资源；Finalize不能保证立即是否非托管资源，其执行时间不确定。
- 类和结构都可以实现IDispose；只有类可以重写Finalize。
- Finalize会使对象复活一次，即需要两次GC才最终完成回收工作。

## 52、.NET托管堆中是否可能存在内存泄露的现象？

是的，可能会。比如：

- 不正确使用静态字段，导致大量数据无法被GC释放。
- 没有正确执行`Dispose()`或不正确使用`Finalize()`，非托管资源没有得到释放。
- 没有手动注销事件。
- 当一个查询语句查询出来的数据量很大并存放到datatable或dataset中是也会造成内存泄露，可以采用分页查询等避免。

## 55、C#中的List如何实现扩容？

`List`仍然使用数组来存储数据，只是封装了扩容。使用ILSpy查看`List`源码，`List`默认容量为4，初始化时不指定则为0。

``` C#
private T[] _items;
private const int _defaultCapacity = 4;

public void Add(T item) {
    if (_size == _items.Length) EnsureCapacity(_size + 1);
    _items[_size++] = item;
    _version++;
}

private void EnsureCapacity(int min) {
    if (_items.Length < min)
    {
        int newCapacity = _items.Length == 0 ? _defaultCapacity : _items.Length * 2;
        if ((uint)newCapacity > Array.MaxArrayLength) newCapacity = Array.MaxArrayLength;
        if (newCapacity < min) newCapacity = min;
        	Capacity = newCapacity;
    }
}
```

当往`List`中添加元素时，如果超出容量，`List`会以原数组两倍的长度新建一个数组。如果该容量大于数组最大长度且够用，则容量修改为数组最大长度。如果该容量大于数组最大长度但仍不够用，则将容量修改为所需长度。将原数组的数据复制到新数组，最后将新数组的引用赋给原数组。

## 62、简述StringBuilder和String的区别

`String`是字符串常量。`StringBuffer`是字符串变量 ，线程安全。`StringBuilder`是字符串变量，线程不安全。

## 80、二叉树的所有遍历方式的原理及优缺点

- 前序遍历，先访问根节点在访问左节点在访问右节点。
- 中序遍历，先访问左节点在访问根节点在访问右节点。
- 后序遍历，先访问左节点在访问右节点在访问根节点。

前中后代表的是访问根节点的时序。这一点上没有什么本质上的优缺点，要看实际需求决定采用何种遍历方式：递归方式和非递归方式。

前者优点是直观，编写起来简单，缺点是但其开销也比较大。非递归形式开销小，但编写复杂。

## 81、数据结构中数组和链表各有什么特点，什么场合下应该使用数组，什么场合下应该使用链表？

从内存存储来看：

- 数组是顺序结构，在内存中连续存储，大小固定，扩容成本大。
- 链表是链式结构，使用指针进行非连续存储，不存在大小限制，动态扩容。

从性能来看：

- 数组支持随机访问，时间复杂度为O(1)；而链表需要逐个访问，时间复杂度为O(n)。
- 数组的插入和删除麻烦，时间复杂度为O(n)；链表的则为O(1)。

从上面的比较可以看出，如果需要快速访问数据，很少或不插入和删除元素，就应该用数组；相反， 如果需要经常插入和删除元素就需要用链表数据结构了。

## 82、用过哪些设计模式？谈谈自己比较熟悉的设计模式

工厂模式，代理模式，策略模式，观察者模式，单例模式。

工厂模式：简单工厂模式解决的问题是如何去实例化一个合适的对象。
简单工厂模式的核心思想就是：有一个专门的类来负责创建实例的过程。凡是出现了大量的产品需要创建，并且具有共同的接口时，可以通过工厂方法模式进行创建。比如说写技能是一系列类，那么就可以使用工厂模式创建。

代理模式：一个是真正的要访问的对象（目标类），一个是代理对象。真正对象与代理对象实现同一个接口，先访问代理类再访问真正要访问的对象。代理模式就是多一个代理类出来，替原对象进行一些操作，比如在租房子的时候回去找中介，因为租客对该地区房屋的信息掌握的不够全面，希望找一个更熟悉的人去做，此处的代理就是这个意思。

代理模式的应用场景：如果已有的方法在使用时需要对原方法进行改进，此时有两种办法：修改原有的方法，违反开闭。采用一个代理类调用原有的方法，且对产生的结果进行控制（代理模式）。使用代理模式，可以将功能划分的更加清晰，有助于后期维护！

策略模式：定义一系列算法，并将每个算法封装起来，使他们可以相互替换，且算法的变化不会影响到使用算法的客户。策略模式的决定权在用户，系统本身提供不同算法的实现，新增或者删除算法，对各种算法做封装。因此，策略模式多用在算法决策系统中，外部用户只需要决定用哪个算法即可。

观察者模式：类似于邮件订阅和RSS订阅。当一个对象变化时，其它依赖该对象的对象都会收到通知，并且随着变化！对象之间是一对多的关系。

单例对象（Singleton）是一种常用的设计模式。在C#应用中，单例对象能保证在一个CLR中，该对象只有一个实例存在。这样的模式有几个好处：某些类创建比较频繁，尤其是大型对象（很大的系统开销），降低了系统内存的使用频率，减轻GC压力；有些类如任务系统控制器控制着任务流程，如果该类可以创建多个的话，系统完全乱了，所以只有使用单例模式，才能保证某些控制器独立控制整个流程。

## 83、请说出 4 种面向对象的设计原则，并分别简述它们的含义

单一职责：一个类只做好一件事情，不要为类设计过多的功能。

开闭原则：对扩展开放，对修改关闭。允许在不修改源代码的情况下对其行为进行扩展。

里氏替换：父类出现的地方可以被子类替换，在替换后依然保持原功能。

依赖倒置：依赖抽象。高层模块不依赖于底层模块，二者都依赖于抽象；抽象不依赖于具体，具体依赖于抽象。

接口隔离：尽量定义小而精的接口，少定义大而全的接口。

面对接口编程：客户端通过一系列抽象操作实例，而无需关注具体类型。

迪米特法则：类与类交互时，在满足功能要求的基础上，传递的数据越少越好。

## 85、程序集

程序集Assembly是通过编译得到的，供进一步编译执行的中间程序，在Window系统上通常为dll库文件或者exe可执行文件。程序集是一个逻辑单元，包含了模块Module，模块又包含了类型Type，类型则包含了各种成员。

程序集可以用于反射，允许在运行时获取不了解的类型及其成员，但由于使用字符串进行元数据搜索以及反射调用属性和方法时需要将参数打包pack、解包unpack而性能差，因此使用多态以减少反射的使用。

程序集可以通过Assembly.Load/LoadFrom和AppDomain.Load手动加载，其中AppDomain.Load得到的程序集是按值封装的，由于AppDomain的不同，CLR会调用线程所在AppDomain重新加载程序集，导致该程序集会被加载到两个AppDomain中。
